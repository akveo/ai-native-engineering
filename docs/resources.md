# Resources

These projects and techniques are inputs to our work, not endorsements of their
entire workflow. Use them to study concrete solutions, then adopt the parts that
solve a demonstrated problem in your project.

## Engineering workflows and methods

### [AI Hero skills](https://www.aihero.dev/skills)

Matt Pocock's collection includes focused skills for refinement, specifications,
ticket decomposition, implementation, testing, review, prototyping, and domain
modeling. The collection is useful for studying narrow triggers and clear
handoffs between activities.

### [OpenSpec](https://github.com/Fission-AI/OpenSpec)

A lighter, iterative spec-driven layer for coding agents, including brownfield
projects. Study its separation of current system specifications from proposed
changes, and its pairing of requirements with concrete scenarios.

### [GitHub Spec Kit](https://github.com/github/spec-kit)

A spec-driven workflow built around specification, planning, tasks, and
implementation. Study its artifact templates, ambiguity checks, and
traceability across stages when a team needs a more formal process for complex
work.

### [Superpowers](https://github.com/obra/superpowers)

An opinionated software-development methodology packaged as composable agent
skills. Study how it turns design discussion, planning, isolated execution,
testing, review, and verification into behavior an agent is expected to follow.

### [Agent Skills](https://github.com/addyosmani/agent-skills)

A collection of engineering skills organized around a lifecycle of define,
plan, build, verify, review, and ship, drawing on Google's engineering
practices. Study how each skill pairs a step-by-step process with verification
requirements and a list of excuses agents use to skip steps, and how
specialist reviewer agents and shared checklists support the workflow.

### [Microsoft HVE Core: RPI](https://github.com/microsoft/hve-core/blob/main/docs/rpi/README.md)

An evidence-led Research–Plan–Implement–Review lifecycle. Study its readiness
checks, durable phase artifacts, and explicit routing of findings back to the
earliest activity that can resolve them.

### [BMad Method](https://github.com/bmad-code-org/BMAD-METHOD)

An adaptive framework spanning idea exploration, research, planning, technical
design, implementation, and review. Study how it varies planning depth with the
size of the work, carries context through artifacts, and offers focused thinking
activities without requiring every task to run the complete process.

### [Cursor plugins](https://github.com/cursor/plugins)

A broad collection of agent plugins and skills. The
[`pstack`](https://github.com/cursor/plugins/tree/main/pstack) plugin is an
especially useful reference for investigation, review, verification, technical
writing, and capturing a developer's working conventions.

### [Compound Engineering](https://github.com/EveryInc/compound-engineering-plugin)

A plugin-based method for making each unit of engineering work improve later
work. Study how it turns discoveries into better tests, documentation, tools,
and reusable agent guidance.

## Agent knowledge

### [Open Knowledge Format](https://github.com/GoogleCloudPlatform/open-knowledge-format)

Google Cloud's spec for agent-readable knowledge: Markdown files, one concept
each, with YAML frontmatter and links between concepts. Study its v0.2 fields
for provenance, verification, and staleness.

## Visual design

### [Impeccable](https://impeccable.style/)

Agent guidance and a shared vocabulary for critiquing and improving interface
design. Study its focused commands and catalog of common generated-UI problems.

### [Taste Skill](https://www.tasteskill.dev/)

Design rules and component guidance intended to steer coding agents toward more
purposeful interfaces and away from generic templates.

## How to add a resource

Add a resource when it teaches a reusable technique or provides a concrete
implementation.

Avoid a bare list of links. Recheck resources periodically because tools and
agent workflows change quickly.
